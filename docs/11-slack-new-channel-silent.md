# Slack 새 채널에서 봇이 조용할 때 — 점검표 (ThisCode)

> 봇에게 이 문서를 주고 「이 순서대로 확인하고 고쳐 줘」라고 하면 됩니다. 토큰 값은 절대 채팅에 붙이지 마세요.
> macOS·Linux·WSL 터미널 기준입니다. Windows PowerShell 에서는 아래 설정 조회 명령이 그대로 돌지 않으니 WSL 에서 실행하세요.

## 한 줄 결론
TEST 채널에서는 되는데 새 채널에서는 안 되는 경우, 가장 흔한 원인은 **봇 설정 파일(.env)의 「허용 채널」이 TEST 채널 ID 하나로 고정**돼 있어서입니다. 새 채널 ID를 더하거나, 끝에 `*`를 붙여 「초대된 모든 채널」로 열면 됩니다. 그 다음 순서로 **봇 초대 → 봇끼리 허용 목록 → 진짜 @멘션**을 봅니다. Slack 앱 설정(권한·이벤트)은 TEST에서 이미 동작하고 있다면 원인일 가능성이 낮지만, 새 채널이 **비공개**면 예외입니다. 그리고 기본 설정은 채널에서 **봇을 @멘션한 글만** 받습니다 — 멘션 없는 글·스레드 후속이 안 들어오는 건 고장이 아닙니다(아래 「공개 채널 메시지」 행).

## 왜 이런 일이 생기나 (구조)
ThisCode의 Slack 연결 프로그램은 메시지를 받으면 세 번 거릅니다. 하나라도 걸리면 **아무 말 없이 버립니다** — 그래서 「에러도 안 나고 그냥 조용」합니다.

1. **채널 거르기**: `SLACK_CHANNEL_ID`에 적힌 채널만 듣는다.
2. **발신자 거르기**: 사람은 `ALLOWED_SLACK_USER_ID`, 봇은 `ALLOWED_SLACK_BOT_USER_IDS`에 적힌 ID만 받는다.
3. **멘션 거르기**: 봇이 보낸 글은 받는 봇을 진짜 `@멘션`한 것만 받는다.

각 봇은 **자기 설정 파일이 따로** 있습니다. A봇이 B봇을 불렀는데 B가 조용하면 **B의 설정**을 봅니다.

## 순서대로 확인 (위부터 — 대부분 1~2번에서 끝남)

| # | 무엇을 확인 | 왜 조용해지나 | 어떻게 고침 | 확인 |
|---|---|---|---|---|
| 1 | 봇 설정 파일의 `SLACK_CHANNEL_ID`에 새 채널 ID가 있나? | TEST 채널 ID만 적혀 있으면 새 채널 메시지는 코드에서 버림 | 기존 값 뒤에 쉼표로 새 채널 ID를 추가. 채널마다 고치기 싫으면 끝에 `,*`를 붙임(예: `C기존ID,*`) — 그러면 **봇을 초대한 모든 채널**을 듣습니다. 고친 뒤 그 봇의 연결 프로그램(server.ts)을 띄워 둔 곳(터미널 탭·tmux 등)에서 끄고 다시 실행. `*`를 붙이면 누구든 봇을 초대한 채널의 글을 받고 그 채널에 답도 할 수 있게 되니, 그게 싫으면 채널 ID만 더하세요(README의 `*` 경고와 같은 뜻) | 아래 「설정 조회」로 값 확인 → 새 채널에서 `@봇이름 PONG만 답해 주세요` |
| 2 | 봇이 새 채널에 **초대**돼 있나? | 초대 안 된 채널은 Slack이 봇에게 메시지를 보내지 않음. `*` 설정이면 초대가 곧 청취 조건 | 새 채널에서 `/invite @봇이름` — 받는 봇마다 | 채널 이름 클릭 → 통합 → 앱 목록에 봇이 있나 |
| 3 | 봇→봇 호출이면, 부르는 봇의 ID가 **받는 봇의** `ALLOWED_SLACK_BOT_USER_IDS`에 있나? | 목록에 없는 봇의 글은 조용히 버림. 보낸 쪽은 성공으로 보임. 봇을 새로 추가했을 때 **기존 봇 전원**의 목록을 갱신 안 하면 생김 | 받는 봇 설정에 `U`로 시작하는 봇 사용자 ID를 쉼표로 추가 후 1번과 같은 방법으로 다시 실행 | 같은 발신자로 TEST와 새 채널에 같은 호출 |
| 4 | 진짜 `@멘션`인가? | 글자로 「봇이름」만 쓰면 멘션이 아님. 봇→봇은 매번 멘션 필요 | Slack 자동완성으로 봇을 골라 멘션 | 새 최상위 글로 `@봇이름 PONG만 답해 주세요` |
| 5 | TEST에서는 「기존 스레드 안」에서 답한 거 아닌가? | 기본 설정에선 스레드 안에서도 매번 멘션이 필요(멘션 없이 이어지는 건 선택 구독 `message.channels` 를 켠 봇만). 새 채널의 첫 호출도 멘션이 필요. 재시작하면 스레드 기억도 초기화 | 새 채널에서도 매번 멘션 | 최상위 멘션 호출로 비교 |
| 6 | 새 채널이 **비공개**(자물쇠)인가? | 공개 채널용 권한만 있으면 비공개 채널 글은 안 들어옴 | 아래 Slack 앱 설정표의 「비공개 채널」 항목 | 두 채널의 공개/비공개를 나란히 비교 |

## Slack 앱 설정 — 어디를 누르고 무엇을 보나
[Slack 앱 관리](https://api.slack.com/apps)에서 **받는 봇의 앱**을 고릅니다. 「이벤트」는 Slack이 봇에게 알려 주는 메시지 종류, 「권한」은 앱이 읽고 보낼 수 있는 범위입니다. 둘 다 맞아야 합니다.

| 설정 항목 → 빠졌을 때 증상 | 어디서 고치나 | 확인 |
|---|---|---|
| **채널 참여**: TEST에만 초대했으면 새 채널 글은 안 들어옴 | 새 채널에서 `/invite @봇이름` | 채널 → 통합 → 앱 목록 |
| **공개/비공개**: TEST는 공개인데 새 채널이 비공개면 필요한 이벤트·권한이 달라짐 | 채널 정보에서 자물쇠 확인 → 아래 비공개 항목 적용(공개로 바꿀 필요 없음) | 두 채널 나란히 비교 |
| **공개 채널 메시지** `message.channels` → 기본 설정은 이 구독을 **일부러 뺍니다**(채널 글 «수정»까지 받아 시간당 1,000건을 넘기면, 봇 호스트가 꺼졌을 때 Slack 이 이벤트 구독을 자동으로 끔). 그래서 멘션만 되고 일반 글·스레드 후속은 원래 안 들어옴 — 고장 아님 | 늘 켜진 호스트에서만, 꼭 필요하면 Event Subscriptions → Subscribe to bot events에 `message.channels` 추가(`channels:history` 권한은 기본에 있음) | 멘션 글은 들어오고 멘션 없는 글은 안 들어오면 정상 |
| **봇 멘션** `app_mention` + `app_mentions:read` 빠짐 → 기본 설정에선 채널에서 아무 글도 안 들어옴(채널 수신의 유일한 경로) | 같은 두 화면에서 각각 추가 | 자동완성 멘션으로 호출 |
| **비공개 채널 메시지** → 기본 설정에선 비공개 채널도 @멘션 글은 `app_mention` 으로 들어옴(봇 초대 필요 · 공식 문서상 필요한 권한은 `app_mentions:read` 뿐 — 비공개 채널 실측은 아직 없음). 멘션 없는 글까지 받으려면 `message.groups` + `groups:history`(선택 — 늘 켜진 호스트에서만) | 봇 초대 확인 · 선택 시 Event Subscriptions에 `message.groups`, Bot Token Scopes에 `groups:history` 추가 | 비공개 채널에서 첫 멘션·후속 각각 확인 |
| **채널 정보 조회** `channels:read`(공개) · `groups:read`(비공개) 빠짐 → 설정 도구의 채널 검색이 실패. 수신 자체의 필수 조건은 아님 | 설정 도구가 권한 부족을 알릴 때 추가 | 채널 목록 다시 조회 |
| **답장 권한** `chat:write` 없음 → 받아도 답을 못 보냄. TEST에서 답하고 있다면 이건 원인 아님 | Bot Token Scopes에 `chat:write` | 실제 답장 도착 |
| **권한 바꾼 뒤 재설치 안 함** → 화면엔 권한이 있는데 옛 권한으로 동작 | OAuth & Permissions → Reinstall to Workspace(앱 삭제 불필요) | 승인 화면에 새 권한이 보이는지 |
| **Socket Mode 꺼짐** → TEST·새 채널 둘 다 조용함 | Socket Mode 켜기 + 연결 프로그램 접속 상태 | 두 채널 모두 호출 |

`groups:*`는 권한 하나의 이름이 아니라 비공개 채널 권한 묶음을 부르는 말입니다. 필요한 건 `groups:history`(글 수신)와, 설정 도구가 요구할 때 `groups:read`입니다. DM은 따로 `message.im` + `im:history`를 씁니다.

## 설정 조회 (토큰은 출력하지 않음)
실행 중인 봇의 설정 폴더는 기본 `~/.claude/channels/slack`, 따로 뒀다면 실행 설정의 `CLAUDE_CHANNEL_SLACK_DIR` 값입니다. 아래는 세 항목만 읽습니다. `.env` 전체를 채팅에 붙이지 마세요.

```sh
python3 - <<'PY'
import os
from pathlib import Path
folder = Path(os.environ.get('CLAUDE_CHANNEL_SLACK_DIR', '~/.claude/channels/slack')).expanduser()
keys = {'SLACK_CHANNEL_ID', 'ALLOWED_SLACK_USER_ID', 'ALLOWED_SLACK_BOT_USER_IDS'}
seen = set()
for line in (folder / '.env').read_text().splitlines():
    key, sep, value = line.strip().partition('=')
    if sep and key in keys:
        print(key + '=' + value.strip())
        seen.add(key)
for key in sorted(keys - seen):
    print(key + '=(미설정)')
PY
```

읽는 법: `SLACK_CHANNEL_ID`에 새 채널 ID도 `*`도 없으면 → 1번. `ALLOWED_SLACK_BOT_USER_IDS`가 비었거나 부르는 봇이 없으면 → 3번. `*`만 단독으로는 넣을 수 없고 반드시 `C채널ID,*` 꼴이어야 합니다.

## 이 문서의 근거와 한계
- 기준 코드: ThisCode 공개판(`vendor/claude-channel-server/src/config.ts`·`server.ts`). 세 번 거르는 구조·`*` 처리는 코드에서 확인했고, Slack 권한 이름은 Slack 공식 문서와 대조했습니다.
- 「새 채널마다 설정을 고치지 않게 `*`로 여는」 방식은 ThisCode 운영 중 같은 문제가 되풀이돼 2026-09-23 판에 넣은 기능입니다. 봇끼리 허용 목록 누락·채널 미초대도 운영 중 실제로 여러 번 겪은 원인입니다.
- 로컬 재현: 수신 조건 9개를 코드로 돌려 모두 예상대로였습니다(TEST 허용 · 새 채널 ID 빠지면 거부 · 추가하면 허용 · 봇 ID 빠지면 거부 · 멘션 없으면 거부). **실제 Slack에서 새 채널을 만들어 돌린 재현은 아직 하지 않았습니다** — 사용자 환경의 원인을 확정한 문서가 아니라 점검 순서입니다.
